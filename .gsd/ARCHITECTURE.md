## Data Flow

1. **User Profile Ingestion**: User uploads PDF resume -> `local-resume-extractor.js` parses text via `pdf-parse` -> `resume-to-profile.js` runs LLM extraction -> normalized JSON stored in `data/profile.json`.
2. **Job Fetching & Scoring**: Cron / manual trigger runs `fetch-all-boards.js` -> queries registered country job boards -> `llm-provider.js` scores relevance against profile via `prompts/job-scoring.txt` -> jobs persisted in `data/jobs.json`.
3. **Application & Tailoring**: User triggers custom tailoring -> `tailor-engine.js` generates role-specific resume bullet points & cover letter -> `generate-resume-pdf.js` compiles tailored PDF via `pdfkit`.

## Technical Debt & Observations

- [ ] **No central database ORM**: Uses file-based JSON storage (`data/jobs.json`, `data/profile.json`). Works well for single-user desktop agent, but requires mutex/file locking under heavy concurrent writes.
- [ ] **Frontend Script Coupling**: Vanilla JS client files (`public/js/*.js`) rely on global scope variables without a bundler.
- [ ] **No formal test framework**: Uses custom Node.js runner scripts (`node tests/...`) instead of Jest/Vitest.

## Conventions

- **Naming:** Kebab-case for scripts (`resume-to-profile.js`, `fetch-all-boards.js`), camelCase for module exports.
- **Structure:** `src/routes/` for API routes, `scripts/engine/` for heavy business logic, `scripts/core/` for data access.
- **Testing:** Standalone node script runners asserting runtime output and exit codes.
