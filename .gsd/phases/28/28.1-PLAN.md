# Plan 28.1: Profile vs Search Preferences Decoupling (Single Current Role & Resident City in Profile, Multi-Target Roles in Settings)

## Objective
Decouple the Master Profile ("My Resume and Profile") from Search Preferences:
1. "My Resume and Profile" represents the candidate's current personal baseline: exactly ONE current role (e.g., current job title or title at the top of resume) and ONE resident location (where the user currently lives).
2. The automatic market role discovery engine (4-10 calibrated job titles) and target search locations route exclusively into **Settings** (`settings.target_titles` / `settings.locations`), where search preferences are managed.
3. Remove backward-synchronization from `settings.js` into `master-profile.json` so user settings do not overwrite the master profile with multiple target roles.

## Context
- `public/index.html` (lines 1480-1530: `prof-location`, `prof-target-roles` input fields)
- `public/js/profile.js` (`populateProfileForm`, `syncFormToJson`, `handleResumeFileSelected`)
- `src/routes/profile.js` (resume parsing & profile endpoints)
- `src/routes/settings.js` (POST `/api/settings` and profile sync)
- `scripts/core/settings-helper.js` (`syncProfileToSettings`)
