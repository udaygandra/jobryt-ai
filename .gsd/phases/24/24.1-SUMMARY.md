# Plan 24.1 Summary: Per-Task Search Context & Bounded-Concurrency Fetch Pool

**Status:** Complete

## Delivered
- `scripts/engine/fetch-pool.js` (new): `runPool` (global cap 12, isolated failures) and `hostFetch` (per-host caps: LinkedIn 2 + 150ms gap, Job Bank 3, Adzuna 4, others 4; 10s timeout; 2 retries with jittered backoff on 429/5xx/network; honours `Retry-After`).
- `fetch-all-boards.js`:
  - All 15 fetchers now read role/location from `CTX` (AsyncLocalStorage-backed), so (role x location x board) tasks run concurrently without shared mutable state.
  - All 20 `fetch(` calls in fetchers go through `hostFetch`.
  - `fetchAllJobs` builds the cartesian task list and runs it through `runPool`; the 800ms inter-pair sleep is gone.
  - Adzuna pages 1-3 and LinkedIn detail pages now run concurrently (pacing enforced by `hostFetch`).
  - Overlapping scans are queued (`scanLock`) because settings and the collector array are still module-level.

## Deviation from plan
- Used `AsyncLocalStorage` instead of threading a `ctx` parameter through every fetcher signature: same isolation, ~70 fewer changed call sites. The `CTX` getter falls back to the module globals, so `setSearchContext` and existing tests are unchanged.
