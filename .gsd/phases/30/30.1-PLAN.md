# Plan 30.1: True Full Reset (Zero-Residue Wipe of Profile, Resumes, Settings & Queues) & Settings Persistence Integrity

## Objective
Deliver a genuine, zero-residue "Start from Fresh (Full Reset)" backend and frontend execution: wipe master profile, erase uploaded resume documents, purge job database/queues, and reset search settings to a clean slate without firing premature background scans on an empty profile. Fix the settings loading engine so user changes to target roles, country scope, and cities persist permanently and are never overwritten by stale profile data.

## Context
- `src/routes/settings.js`
- `src/routes/profile.js`
- `scripts/core/settings-helper.js`
- `scripts/core/jobs-db.js`
- `public/js/settings.js`

## Tasks

<task type="auto">
  <name>Implement True Zero-Residue Backend Factory Reset & Cancel Premature Scans</name>
  <files>src/routes/settings.js, scripts/core/settings-helper.js, src/routes/profile.js</files>
  <action>
    - In `src/routes/settings.js` inside `POST /api/settings/reset` for `action === 'fresh_start'`:
      1. Purge all pipeline databases and tracking records via `jobsDb.clearPipelineData()`.
      2. Clear `data/tracking/last_scan_result.json` and reset `activeScanState` to idle if running.
      3. Wipe `master-profile.json` in `data/profiles/` by resetting it to a clean empty state:
         ```json
         {
           "name": "",
           "role": "",
           "contact": {},
           "skills": [],
           "experience": [],
           "education": [],
           "target_titles": [],
           "locations": [],
           "writing_sample": ""
         }
         ```
      4. Remove any uploaded temporary or parsed resume files in `data/profiles/` matching `upload-*` or `.pdf`/`.txt`/`.docx` candidate files.
      5. Factory reset `data/config/settings.json` with clean empty arrays for roles and locations:
         ```javascript
         {
           freshness_hours: 24,
           score_threshold: 70,
           commute_radius_km: 25,
           work_type: 'Open to All',
           country_scope: 'AUTO',
           timezone: getSystemTimezone(),
           target_titles: [],
           target_roles: [],
           locations: [],
           target_locations: [],
           boards_enabled: { ...allDefaultsOn }
         }
         ```
      6. REMOVE the automatic background call to `executePipelineScan({ source: 'fresh_start' })`. A factory reset must leave the system in a clean, idle state awaiting user configuration.
    - In `scripts/core/settings-helper.js`:
      * In `updateSettings` and `sanitizeSettings`, ensure `target_titles` and `target_roles`, as well as `locations` and `target_locations`, are kept bidirectional and synchronized. If an empty array `[]` is passed in `partial`, allow it to overwrite previously stored roles/locations rather than falling back to defaults.
  </action>
  <verify>node -e "const s = require('./src/routes/settings'); console.log('Reset handler ready');"</verify>
  <done>Full reset completely wipes profile, uploaded resumes, job tracking queues, and resets settings to clean empty state without auto-launching an empty scan.</done>
</task>

<task type="auto">
  <name>Fix Settings Loading and Saving Engine in Frontend Client</name>
  <files>public/js/settings.js</files>
  <action>
    - In `public/js/settings.js`:
      * In `loadSettings()`:
        - Populate `window.targetRolesList` directly from `currentSettings.target_titles` or `currentSettings.target_roles`.
        - Populate `window.targetLocationsList` directly from `currentSettings.locations` or `currentSettings.target_locations`.
        - ONLY if both `currentSettings.target_titles` and `currentSettings.target_roles` are completely absent/empty, allow optional fallback to `profData`.
        - NEVER overwrite `window.targetRolesList` or `window.targetLocationsList` if settings already define them.
        - Respect `currentSettings.country_scope`: if user set a specific country (e.g. `'CA'`, `'US'`, `'GB'`), maintain it; do not let `AUTO` or profile auto-detection override a user's explicit country selection.
        - Call `renderRoleTags()` and `renderLocationTags()`.
      * In `saveAllSettings()`:
        - Send `{ target_titles: window.targetRolesList, target_roles: window.targetRolesList, locations: window.targetLocationsList, target_locations: window.targetLocationsList, country_scope: scope, ... }`.
        - Update in-memory `currentSettings` with the newly saved values so immediate UI state and subsequent visits match exactly without page reload.
      * In `resetAction('fresh_start')`:
        - After successful reset API response, clear `window.targetRolesList = []`, `window.targetLocationsList = []`.
        - Clear `localStorage.removeItem('jobryt_cached_pending_jobs')`.
        - Re-render empty tag containers (`renderRoleTags()`, `renderLocationTags()`).
        - Reset Master Profile form fields in UI if present (`#prof-name`, `#prof-current-role`, `#prof-location`, etc.).
  </action>
