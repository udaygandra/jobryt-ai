# Plan 30.1 Summary: True Zero-Residue Factory Reset & Settings Persistence Integrity

## Overview
Implemented a genuine, zero-residue "Start from Fresh (Full Reset)" execution across the backend and frontend. Resolved the settings loading bug where user modifications to target roles, country scope, or target cities in Settings were being overwritten by stale `master-profile.json` data upon subsequent visits or page reloads.

## Key Changes
1. **Backend Factory Reset (`src/routes/settings.js`)**:
   - In `POST /api/settings/reset` for `fresh_start`:
     - Calls `jobsDb.clearAllTrackingData()` (purges seen jobs, pending opportunities, rejected listings, tailored resumes, recruiter caches).
     - Deletes `data/tracking/last_scan_result.json`.
     - Completely resets `data/profiles/master-profile.json` to a clean empty initial schema (`name: ''`, `role: ''`, `contact: {}`, `skills: []`, `experience: []`, `education: []`, `target_titles: []`, `locations: []`, `writing_sample: ''`).
     - Unlinks any uploaded resume documents (`upload-*`, `.pdf`, `.docx`, `.txt`) in `data/profiles/`.
     - Calls `settingsHelper.factoryResetSettings()` to reset `settings.json` to clean factory defaults with empty arrays for roles and locations.
     - **Removed premature scan execution**: Completely eliminated the automatic background call to `executePipelineScan({ source: 'fresh_start' })` that was locking the pipeline and scanning with empty/fallback criteria.

2. **Bidirectional Settings Synchronization (`scripts/core/settings-helper.js`)**:
   - `sanitizeSettings` and `updateSettings` maintain bidirectional synchronization between `target_titles` and `target_roles`, as well as `locations` and `target_locations`.
   - Explicit empty arrays (`[]`) are honored rather than falling back to default values.
   - Added and exported `factoryResetSettings()`.

3. **Frontend Settings Loading & Saving Integrity (`public/js/settings.js`)**:
   - In `loadSettings()`: strictly loads `window.targetRolesList` and `window.targetLocationsList` directly from `currentSettings` first. It no longer overwrites saved settings with `profData`.
   - In `saveAllSettings()`: transmits bidirectional keys (`target_titles`, `target_roles`, `locations`, `target_locations`) and updates in-memory `currentSettings` immediately.
   - In `executeSettingsReset('fresh_start')`: clears client-side state (`window.targetRolesList = []`, `window.targetLocationsList = []`), clears `localStorage` job caches, re-renders empty tag containers, and clears profile UI fields.
