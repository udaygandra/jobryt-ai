# Plan 30.2 Summary: Pre-Scan Comprehensive Validation Engine

## Overview
Implemented strict pre-scan validation across both frontend and backend to protect system resources and prevent meaningless scans from executing with zero roles, zero locations, all boards disabled, or a completely blank candidate profile. Built a modern Scan Readiness Guard Modal with 1-tap navigation to guide users directly to the incomplete fields.

## Key Changes
1. **Backend Validation Gate (`src/routes/pipeline.js`)**:
   - Implemented and exported `validateScanCriteria({ targetTitles, targetLocations, boardsEnabled, profile })`:
     - **Roles Check**: requires at least 1 real job title (rejects empty or placeholder values like "Target Role").
     - **Locations Check**: requires at least 1 target city, state/province, or "Remote".
     - **Boards Check**: verifies at least 1 job board is enabled in `settings.boards_enabled`.
     - **Profile Baseline Check**: verifies candidate profile has authentic data (at least one of: role, skills, experience, or summary) so AI scoring and heuristic gates have an authentic baseline.
   - In `executePipelineScan`: rejects scans failing validation with `{ success: false, status: 'validation_failed', validationErrors: [...] }`.
   - In `POST /api/pipeline/run`: returns HTTP 422 Unprocessable Entity when `status === 'validation_failed'`.
   - Added `GET /api/pipeline/validate` endpoint to allow fast client-side pre-flight checks.

2. **Frontend Scan Readiness Guard Modal (`public/index.html`)**:
   - Added `#scan-validation-modal` with amber caution badge and clear copy.
   - Included dynamic visual checklist container `#scan-validation-checklist` that details missing setup requirements.
   - Included 1-tap action buttons:
     - `#btn-fix-settings`: navigates to Search Settings tab and focuses the role tag input.
     - `#btn-fix-profile`: navigates to My Resume & Profile tab.
     - Dismiss button.

3. **Frontend Guardrail Interception (`public/js/opportunities.js`)**:
   - Implemented `validateScanPreconditions()`: calls `/api/pipeline/validate` and displays `#scan-validation-modal` if requirements are unfulfilled.
   - Updated `triggerPipelineScan()`: runs pre-flight validation before opening the scan progress modal, and intercepts HTTP 422 responses from the server.
   - Implemented `showScanValidationModal(errors)`, `closeScanValidationModal()`, `goToSettingsFromValidation()`, and `goToProfileFromValidation()`.
