# Phase 20.3 Summary: Fix Container Read-Only .env Mount & API Key Persistence Resilience (EROFS Fix)

## Objective Achieved
Eliminated the `Error: EROFS: read-only file system, open '/app/.env'` error thrown during Adzuna and USAJOBS API key validation in the Web UI.

## Key Changes
1. **Docker Compose Mount Update (`docker-compose.yml`)**:
   - Removed the `:ro` flag from the `.env` volume mount:
     - Before: `- ${ENV_FILE:-.env}:/app/.env:ro`
     - After:  `- ${ENV_FILE:-.env}:/app/.env`
   - Recreated container via `docker compose up -d web` with write capability.
2. **Backend EROFS Resilience (`src/routes/settings.js`)**:
   - In `router.post('/validate-key')` (for Adzuna, USAJOBS) and `router.post('/env')`:
     - Wrapped `.env` file writing in try-catch blocks.
     - Preserves active credentials in `process.env` memory.
     - Persists credentials to `data/config/settings.json` via `settingsHelper.updateSettings(currSettings)` under `currSettings.api_keys`.
     - If the filesystem is read-only, logs a graceful notice without throwing 500 errors to the client.
3. **Startup Credential Hydration (`server.js`)**:
   - On server startup, checks `settingsHelper.getSettings().api_keys` and restores any saved board API keys into `process.env` if not already set.

## Verification
- Verified with `node tests/test-phase20.js` and all static assertions passed.
- Verified Docker container recreation and running status.
