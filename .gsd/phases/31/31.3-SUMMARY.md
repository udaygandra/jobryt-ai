# Plan 31.3 Summary: Balanced HR-Calibrated Scoring Engine & Opportunities Filter Alignment

## Achievements
1. **Elimination of Artificial Score Inflation Floor**:
   - Replaced artificial `60 + (matched / 5) * 40` scoring floor in `computeHeuristicScore()` with an authentic HR-calibrated formula:
     * Analyzes job's explicit tech stack demands using `TECH_SKILL_CATALOG` (80+ tools & data technologies).
     * Calculates candidate match ratio against the job's actual demands with an encouraging HR posture (+20% baseline bonus for transferable qualifications and title alignment).
     * Heavy stacks (10-25 tools) with only 1-3 matched skills now land realistically in the 50-62% range on skills fit (and <= 72% overall), instead of artificially inflating to 85-92%.
     * High match jobs (matching 5+ core tools or >70% of stack) score 85-96% on skills fit (and >= 80% overall).
     * 0 matched skills on technical postings land at 38% skills fit.
2. **Neutral Screening Tier for Unstated Skills**:
   - Updated unstated skills default from inflated 90% to neutral 70% in `computeHeuristicScore()`, `runParseScore()`, and `prompts/job-scoring.txt`.
   - Guaranteed that jobs with unstated technical skills receive a realistic screening score (~76%) rather than automatically qualifying in the top tier (>85%).
3. **LLM Evaluation Stability**:
   - Increased LLM evaluation timeout in `src/routes/pipeline.js` from 4500ms to 7000ms to allow full structured evaluations to finish reliably without falling back to CPU heuristics.
4. **Opportunities Score Filter & UI Alignment**:
   - Added `#opp-threshold-filter-btn` in `public/index.html` dynamically reflecting candidate's configured threshold (e.g. `65%+ Qualified`).
   - Fixed property lookup bug in `public/js/opportunities.js` (`job.score ?? job.match_score ?? job.overall_score`) preventing jobs from disappearing under filter selections.
   - Updated empty state context banner to display dynamic threshold from candidate settings.
   - Exported `updateThresholdFilterButtons` on `window` for reliable DOM synchronization.
