# Plan 18.1: Job Board URL Audit, Ingestion Link Guarantees & Link Enrichment

## Objective
Diagnose why certain jobs in Applications had `Search Job` instead of a direct link, audit all 16 job board fetchers in `fetch-all-boards.js` to guarantee every board populates canonical posting URLs, enrich manual/custom evaluations with realistic links, and backfill existing SQLite records with direct URLs.

## Context
- `scripts/engine/fetch-all-boards.js`
- `src/routes/pipeline.js`
- `tests/test-pdf-resume-parsing.js`
- `scripts/core/jobs-db.js`
- `public/js/applied.js`

## Tasks

<task type="auto">
  <name>Audit All 16 Job Board Adapters & Guarantee Direct Posting URLs</name>
  <files>
    scripts/engine/fetch-all-boards.js
    scripts/engine/node-logic.js
  </files>
  <action>
    - Audit all 16 job board fetchers in `scripts/engine/fetch-all-boards.js` (Adzuna, Canada Job Bank, LinkedIn, USAJOBS, Arbeitnow, Himalayas, Remotive, Jobicy, Indeed, Arbeitsagentur, MyCareersFuture, Seek, Reed UK, Bayt, WTTJ, Naukri, Daijob, Vagas):
      - Ensure every returned item explicitly populates `job_url`, `redirect_url`, and `apply_url`.
      - If any board returns a relative path (e.g. `/job/...`), prefix the base domain to ensure a valid absolute HTTPS URL.
      - If any board response has a missing or empty URL, synthesize a direct board search URL targeting that job title and company (e.g. `https://www.linkedin.com/jobs/search/?keywords=${title}+${company}`).
    - In `scripts/engine/node-logic.js` `normalizeJob`:
      - Ensure `job_url`, `redirect_url`, `apply_url`, `url`, and `link` are all normalized and guaranteed non-empty.
  </action>
  <verify>
    node -e "const { normalizeJob } = require('./scripts/engine/node-logic'); const n = normalizeJob({ title: 'Engineer', company: 'TestCorp', id: '123' }); assert(n.job_url, 'Must have fallback url'); console.log('✅ URL normalization verified:', n.job_url);"
  </verify>
  <done>
    All job board adapters and normalizeJob guarantee valid, absolute URLs for all ingested opportunities.
  </done>
</task>

<task type="auto">
  <name>Enrich Custom Job Evaluation & Backfill Existing SQLite Applied Jobs</name>
  <files>
    src/routes/pipeline.js
    tests/test-pdf-resume-parsing.js
    scripts/core/jobs-db.js
  </files>
  <action>
    - In `src/routes/pipeline.js` (`POST /api/pipeline/evaluate-custom`):
      - If user provided a URL, use it.
      - If URL is omitted, generate a clean canonical URL search link (`https://www.google.com/search?q=${encodeURIComponent(title + ' ' + company + ' job')}`) or board URL so `job_url` is never empty.
    - In `tests/test-pdf-resume-parsing.js`:
      - Add realistic `url: 'https://ca.linkedin.com/jobs/view/senior-power-bi-sql-data-analyst-capital-energy-markets-9988776655'` to the Capital Energy Markets test payload so test jobs committed to SQLite don't lack links.
    - Add a one-time migration / repair script in `scripts/core/jobs-db.js` or standalone script to backfill existing SQLite `applied_jobs` and `pending_jobs` where `job_url` is empty with direct Google job links.
  </action>
  <verify>
    node -e "const { getAppliedJobs } = require('./scripts/core/jobs-db'); const empty = getAppliedJobs().filter(j => !j.job_url); assert.strictEqual(empty.length, 0, 'No applied jobs should have empty job_url'); console.log('✅ All applied jobs have valid URLs');"
  </verify>
  <done>
    No jobs in SQLite database have missing URLs, and custom evaluations always preserve or synthesize valid job links.
  </done>
</task>
