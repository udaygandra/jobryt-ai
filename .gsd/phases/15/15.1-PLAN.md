# Plan 15.1: Smart Country Scope City Reset & Action Button Validation Engine

## Objective
Automatically reset previously selected cities when the user changes target country in Settings so outdated cities from other countries are not retained, and implement a lightweight, non-intrusive action-button validation engine for Settings, Profile, and Tailoring that validates only when users click submit/save buttons.

## Context
- `public/js/settings.js`
- `public/js/profile.js`
- `public/js/utils.js`
- `public/index.html`

## Tasks

<task type="auto">
  <name>smart-country-scope-city-reset</name>
  <files>public/js/settings.js</files>
  <action>
    - In `public/js/settings.js`:
      - Track `previousCountryScope`.
      - In `onCountryScopeChange()`:
        - When `scope` changes to a different country and `window.targetLocationsList.length > 0`:
          - Check if existing locations belong to the new country. Any location from the previous country that doesn't match the new country scope is cleared.
          - If cities are reset, show toast: `Target country changed. Previous cities cleared — please select cities in ${newCountryName}.`
          - Call `renderLocationTags()`.
        - Update `previousCountryScope = scope`.
  </action>
  <verify>grep -n "previousCountryScope" public/js/settings.js</verify>
  <done>Changing country scope clears outdated cities and gives user option to select fresh cities.</done>
</task>

<task type="auto">
  <name>action-button-field-validation-engine</name>
  <files>public/js/utils.js, public/js/settings.js, public/js/profile.js, public/index.html</files>
  <action>
    - In `public/js/utils.js`:
      - Implement a robust `validateFormFields(rules)` helper that:
        - Checks required inputs, formats (email), and list minimums (roles, locations).
        - Highlights invalid elements with a clean error ring (`border-rose-500 focus:border-rose-500 ring-1 ring-rose-500/30`), attaches an accessible helper message beneath the field, and clears the error dynamically when user corrects the field (`input` or `change` event).
        - Scrolls the first invalid field into view smoothly.
        - Returns boolean `isValid`.
    - In `saveAllSettings()` (`settings.js`):
      - Validate on click:
        * Target Roles list must have at least 1 role.
        * Target Country scope must be selected.
        * Target Cities list must have at least 1 city.
      - If invalid, halt save and display toast: `Please complete the required settings fields.`
    - In `saveMasterProfile()` (`profile.js`):
      - Validate on click:
        * Full Candidate Name is required.
        * Email is required and must be valid format.
        * At least 1 target role or profession title is specified.
      - If invalid, halt save and display toast: `Please complete all required profile fields.`
  </action>
  <verify>grep -n "validateFormFields" public/js/utils.js</verify>
  <done>Required field validations trigger only when clicking action buttons with clear visual error cues.</done>
</task>

## Success Criteria
- [ ] Switching target country in Settings resets cities from previous country with helpful toast
- [ ] Clicking "Save Settings" or "Save Profile" highlights missing required fields without annoying keystroke interruptions
