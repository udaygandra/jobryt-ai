# Plan 17.2: Smart LLM State Tracking, Active Model Revisit Logic & Latency Reduction (Priority: gemini-3.8-flash)

## Objective
Implement intelligent, persistent LLM state tracking that eliminates 429 latency by bypassing exhausted models before making network requests, prioritizes `gemini-3.8-flash` as the top model, tracks the exact model used across all operations, and automatically revisits the top model the instant its rate-limit cooldown expires.

## Context
- `scripts/engine/llm-state-manager.js`
- `scripts/engine/llm-provider.js`
- `src/routes/status.js`
- `tests/test-llm-state.js`

## Tasks

<task type="auto">
  <name>Implement Pre-Flight Model Availability Check & Auto-Revisit Engine</name>
  <files>
    scripts/engine/llm-state-manager.js
  </files>
  <action>
    - Ensure `gemini-3.8-flash` is top priority in `WATERFALL`. If `process.env.LLM_MODEL` is set, prepend it as the top priority.
    - Implement pre-flight filtering in `getNextWaterfallModel()`:
      - Cleanly evaluate cooldown timestamps (`blocked_until`).
      - If `nowSec >= blocked_until`, automatically clear the block and mark the model as healthy/available again.
      - Return the highest-priority healthy model immediately without attempting exhausted models.
    - Persist state to `data/tracking/llm_state.json` on every state change so state survives server restarts.
    - Add `getActiveModelInfo()` helper returning:
      - `top_model`: Top desired model (e.g. `gemini-3.8-flash`).
      - `current_active_model`: The model that will be used for the next call.
      - `revisit_in_seconds`: Seconds until top model cooldown expires (0 if active now).
      - `daily_calls_remaining`: Remaining quota.
  </action>
  <verify>
    node tests/test-llm-state.js
  </verify>
  <done>
    Pre-flight filtering selects the highest unblocked model and auto-revisiting restores top model immediately upon cooldown expiry.
  </done>
</task>

  <action>
    - In `scripts/engine/llm-provider.js`:

      - Include `llm.active_model` and `llm.top_model` and `llm.cooldown_seconds` in the `GET /api/status` payload so the frontend displays live model state.
