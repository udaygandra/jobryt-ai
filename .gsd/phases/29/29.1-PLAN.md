# Plan 29.1: Pipeline Scan Mutex, Abort Controller & Last Scan Diagnostics Persistence

## Objective
Implement backend concurrency control (mutex/lock) to block wasteful duplicate scans, an AbortController engine to stop scans mid-flight on demand, real-time status and live log streaming (`GET /api/pipeline/status`), and persistent board-by-board yield tracking (`data/tracking/last_scan_result.json`).

## Context
- `src/routes/pipeline.js`
- `scripts/engine/fetch-all-boards.js`
- `scripts/core/jobs-db.js`
- `data/config/settings.json`

## Tasks

<task type="auto">
  <name>Implement Pipeline Scan State Machine, Concurrency Lock & Abort Controller</name>
  <files>src/routes/pipeline.js</files>
  <action>
    - Add module-level `activeScanState` object to `src/routes/pipeline.js`:
      * `scanId`: unique UUID or timestamp.
      * `status`: 'idle' | 'running' | 'aborted' | 'completed' | 'failed'.
      * `abortController`: AbortController instance.
      * `step`: 'idle' | 'fetching' | 'filtering' | 'scoring' | 'persisting' | 'completed' | 'aborted'.
      * `progress`: { current: 0, total: 0, message: '' }.
      * `logs`: ring buffer of timestamped log entries (up to 100 entries).
      * `boardBreakdown`: map of { [boardName]: count }.
      * `stats`: { totalFetched, freshCount, unseenCount, scoredCount, qualifiedCount, rejectedCount }.
      * `startedAt`, `completedAt`, `durationMs`.
    - In `router.post('/run')` / `executePipelineScan()`:
      * Check `if (activeScanState && activeScanState.status === 'running')`:
        Return HTTP 409 Conflict with `{ success: false, status: 'already_running', message: 'A scan is already in progress', scanId: activeScanState.scanId, startedAt: activeScanState.startedAt }`.
      * Initialize `activeScanState.abortController = new AbortController()`.
      * Pass `signal: activeScanState.abortController.signal` into `fetchAllJobs` and scoring worker pool.
      * In scoring worker pool: check `if (activeScanState.abortController.signal.aborted) return;` at every loop iteration.
      * Calculate per-board count from fetched jobs (`allRawItems`) and populate `boardBreakdown`.
    - Implement `router.post('/stop', ...)`:
      * If scan is running, call `activeScanState.abortController.abort()`, mark status as 'aborted', push log entry, and return `{ success: true, message: 'Scan aborted by user', stats: activeScanState.stats }`.
      * If idle, return `{ success: false, message: 'No scan currently running' }`.
    - Implement `router.get('/status', ...)`:
      * Return current `activeScanState` (or loaded `last_scan_result.json` if idle), including logs, boardBreakdown, stats, step, and status.
  </action>
  <verify>node -e "const { executePipelineScan } = require('./src/routes/pipeline.js'); console.log('executePipelineScan available');"</verify>
  <done>Pipeline endpoints /run, /stop, and /status are implemented with mutex lock, abort capability, and per-board breakdown.</done>
</task>

## Success Criteria
- [ ] Duplicate scan triggers return HTTP 409 and do not execute duplicate fetches or scoring.
- [ ] POST /api/pipeline/stop halts running scans via AbortController.
- [ ] GET /api/pipeline/status provides live logs and board-by-board yield counts.
- [ ] Last scan results persist across server restarts in `data/tracking/last_scan_result.json`.
