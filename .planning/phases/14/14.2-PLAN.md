# Plan 14.2: Standardized City Formatting, Flag Detection & 5-City Guardrail

## Objective
Normalize all city search results from both local datasets and live edge geocoding to a clean, consistent `City, ST, Country` format (e.g., `Redwood City, CA, USA`), ensure accurate country flag detection, and enforce a strict 5-city maximum selection limit to protect free API scoring tiers.

## Context
- `scripts/core/geo-helper.js`
- `public/js/settings.js`
- `public/js/guide.js`
- `public/index.html`

## Tasks

<task type="auto">
  <name>standardize-live-geocoding-format</name>
  <files>scripts/core/geo-helper.js</files>
  <action>
    - In `searchLiveCities()`:
      - Map full US state names to their 2-letter postal codes (e.g. `California` -> `CA`, `New York` -> `NY`, etc.) using state definitions from `data/config/geo-hierarchy.json`.
      - Map full Canadian province names to 2-letter codes (e.g. `Ontario` -> `ON`).
      - Normalize US country naming: `United States` -> `USA`.
      - Ensure formatted string is consistently `City, ST, Country` (e.g. `Redwood City, CA, USA`).
  </action>
  <verify>node -e "require('./scripts/core/geo-helper').searchLiveCities('Redwood City', 'US').then(r => { console.log(JSON.stringify(r[0])); process.exit(r[0].formatted.includes('Redwood City, CA, USA') ? 0 : 1); })"</verify>
  <done>Live geocoding outputs uniform concise `City, ST, Country` strings matching local datasets.</done>
</task>
