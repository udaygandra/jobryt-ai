# Plan 20.3: Fix Container Read-Only `.env` Mount & API Key Persistence Resilience (EROFS Fix)

## Objective
Fix the `Error: EROFS: read-only file system, open '/app/.env'` error encountered when validating and saving API keys (Adzuna, USAJOBS) in the Web UI. Remove the restrictive `:ro` mount flag from `docker-compose.yml` and add resilient fallback storage in `src/routes/settings.js` so that credential validation and activation succeed seamlessly.

## Context
- `docker-compose.yml`: Line 32 has `- ${ENV_FILE:-.env}:/app/.env:ro`
- `src/routes/settings.js`: `router.post('/validate-key')` and `router.post('/env')` write to `.env`
- User screenshots showing EROFS failure on Adzuna and USAJOBS modals

## Tasks

<task type="auto">
  <name>Remove Read-Only Mount Flag from docker-compose.yml</name>
  <files>
    docker-compose.yml
  </files>
  <action>
    - In `docker-compose.yml`:
      - Change line 32:
        From: `- ${ENV_FILE:-.env}:/app/.env:ro`
        To:   `- ${ENV_FILE:-.env}:/app/.env`
      - This allows the running container to write validated credentials to `.env` so they persist across restarts.
  </action>
  <verify>
    node -e "const fs = require('fs'); const dc = fs.readFileSync('docker-compose.yml', 'utf8'); assert(!dc.includes('/app/.env:ro')); assert(dc.includes('/app/.env')); console.log('✅ docker-compose.yml mount verified');"
  </verify>
  <done>
    Docker volume mount allows container process to write to `.env`.
  </done>
</task>

<task type="auto">
  <name>Add EROFS Error Resilience & Fallback Persistence in Settings Route</name>
  <files>
    src/routes/settings.js
  </files>
  <action>
    - In `src/routes/settings.js`:
      - In `router.post('/validate-key')` (for Adzuna, USAJOBS, etc.) and `router.post('/env')`:
        - Wrap `fs.writeFileSync(envPath, ...)` in a try-catch block.
        - Always set `process.env[key] = val` in memory regardless of filesystem write status.
        - Persist credentials to `settingsHelper.getSettings()` / `data/settings.json` under an `encrypted_keys` or `api_keys` dictionary as a persistent fallback so credentials survive even if the filesystem or `.env` is read-only.
        - If `fs.writeFileSync` throws `EROFS` or permission error, log a warning instead of aborting the request with a 500 error, and return success since the key is validated, active in memory, and stored in settings.
  </action>
  <verify>
    node -c src/routes/settings.js
  </verify>
  <done>
    API key validation for Adzuna and USAJOBS succeeds without throwing EROFS errors, and credentials are authenticated, activated, and persisted.
  </done>
</task>

## Success Criteria
- [ ] Adzuna and USAJOBS API key modals validate and activate without EROFS errors
- [ ] Credentials persist to `.env` when writable, and fallback to `data/settings.json` and `process.env` when read-only
- [ ] No unhandled exceptions thrown in `/api/settings/validate-key` or `/api/env`
- [ ] All test suites pass
