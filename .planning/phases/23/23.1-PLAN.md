# Plan 23.1: Clean Board Ingestion Payloads, Reliable Multi-Board Yield & False-Remote Bug Elimination

## Objective
Eliminate false-remote leakages that allow out-of-province hybrid jobs (e.g. Vancouver hybrid roles) to pass geo-filtering, tailor API payloads cleanly to each specific board without confusing or conflicting parameters, and expand the usable candidate yield so users receive a strong, high-volume flow of genuinely in-preference jobs.

## Tasks

<task type="auto">
  <name>Eliminate False-Remote Description Leak in Geo-Filter</name>
  <files>scripts/engine/node-logic.js, scripts/core/geo-helper.js</files>
  <action>
    In `scripts/engine/node-logic.js` (lines 164-169 and line 504):
    - Remove the overly broad `/\b(remote|wfh|telecommute|virtual)\b/i.test(desc)` check. A job that is "Hybrid in Vancouver with in-office and remote days" is NOT a remote job for a Toronto candidate.
    - Strictly classify a job as Remote ONLY when:
      1. Job title explicitly specifies remote (e.g. `(Remote)`, `- Remote`), OR
      2. Job location explicitly specifies remote (e.g. `Remote`, `Canada (Remote)`), OR
      3. Job description explicitly specifies nationwide remote (`100% remote`, `fully remote`, `work from anywhere in Canada`) AND DOES NOT mention required local office / hybrid attendance in an out-of-scope city.
    - If a job is marked "Hybrid" in an out-of-scope city (like Vancouver, BC), it MUST be treated as physical in that city and strictly rejected.
  </action>
  <verify>node -e "const { runGeoFilter } = require('./scripts/engine/node-logic'); const items = [{ json: { title: 'Data Analyst', location: 'Vancouver, BC', description: 'Hybrid role with in-office and remote days in Vancouver.' } }]; const passed = runGeoFilter(items, { locations: ['Toronto, ON'], country_scope: 'CA', work_type: 'Open to All' }); console.assert(passed.length === 0, 'Vancouver hybrid must be rejected'); console.log('PASS: Vancouver hybrid rejected');"</verify>
  <done>Vancouver hybrid job is strictly rejected and cannot leak into the pipeline.</done>
</task>
