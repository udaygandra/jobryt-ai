# Plan 17.3: Universal Multi-LLM Provider Support for Ingestion & Tailoring with Automated Tests

## Objective
Unify resume ingestion (`scripts/engine/resume-to-profile.js`) and ATS resume tailoring (`scripts/engine/tailor-engine.js`) to work seamlessly with all supported LLM providers (Google Gemini, OpenAI, Anthropic Claude, Groq, DeepSeek, OpenRouter, and local Ollama), and create an automated test suite verifying ingestion and tailoring across providers.

## Context
- `scripts/engine/resume-to-profile.js`
- `scripts/engine/tailor-engine.js`
- `scripts/engine/llm-provider.js`
- `tests/test-multi-llm-providers.js`

## Tasks

<task type="auto">
  <name>Refactor Resume Ingestion to Support All LLM Providers</name>
  <files>
    scripts/engine/resume-to-profile.js
  </files>
  <action>
    - In `scripts/engine/resume-to-profile.js`:
      - Remove the hardcoded direct Gemini fetch in `executeWaterfall(payload)`.
      - Integrate with the provider abstraction:
        - If `LLM_PROVIDER` is Gemini, use the smart waterfall with `getNextWaterfallModel()` and cooldown skipping (priority: `gemini-3.8-flash`).
        - If `LLM_PROVIDER` is OpenAI, Claude, Groq, DeepSeek, OpenRouter, or Ollama, dispatch through `callLLMProvider({ prompt, systemInstruction, provider, model })`.
      - Ensure JSON extraction safely handles responses from reasoning models (e.g. DeepSeek-R1 `<think>...</think>` tags) and markdown fenced code blocks (` ```json...``` `).
      - Maintain local regex fallback if LLM is unreachable.
  </action>
  <verify>
    node -c scripts/engine/resume-to-profile.js
  </verify>
  <done>
    Resume parsing executes successfully across any configured LLM provider without provider-specific hardcoding.
  </done>
</task>

<task type="auto">
  <name>Harden Resume Tailoring Across All Provider Output Formats</name>
  <files>
    scripts/engine/tailor-engine.js
  </files>
  <action>

      - Save `model_used` and `provider_used` in the cached `resume.json` metadata and SQLite tracking tables.
      - Maintain zero-fabrication grounding rule regardless of provider used.
  </action>
  <verify>

  </verify>
  <done>

  </done>
</task>
