# Plan 30.2: Pre-Scan Comprehensive Validation Engine (Frontend Guardrails & Backend API Gate)

## Objective
Implement strict pre-scan validation on both frontend and backend to prevent scans from executing with missing or corrupted criteria (e.g., zero target roles, zero target cities, all job boards disabled, or completely blank candidate profile). Provide a modern, actionable Scan Readiness Guard Modal that guides the user to complete missing items with 1-tap navigation rather than failing silently with 0 jobs.

## Context
- `src/routes/pipeline.js`
- `public/js/opportunities.js`
- `public/js/settings.js`
- `public/index.html`

## Tasks

<task type="auto">
  <name>Implement Backend Scan Readiness Validation Gate</name>
  <files>src/routes/pipeline.js</files>
  <action>
    - In `src/routes/pipeline.js`:
      * Inside `executePipelineScan(overrides)`:
        - Check pre-conditions before allocating `activeScanState` or network resources:
          1. **Target Roles Validation**: `targetTitles` must contain at least 1 non-empty, non-placeholder role (reject `['Target Role']` or empty `[]`).
          2. **Target Locations Validation**: `targetLocations` must contain at least 1 non-empty location.
          3. **Active Boards Validation**: At least one job board in `settings.boards_enabled` must be `true`.
          4. **Profile Baseline Validation**: Candidate profile must have at least one of: `role`, `skills` (length >= 1), `experience` (length >= 1), or `summary` so AI scoring and heuristic gates have an authentic candidate basis.
        - If any check fails, return:
          ```javascript
          {
            success: false,
            status: 'validation_failed',
            validationErrors: [
              // Detailed array of failing items: { field: 'roles'|'locations'|'boards'|'profile', message: '...' }
            ],
            message: 'Scan cannot proceed because required search preferences or candidate profile data are missing.'
          }
          ```
      * In `POST /api/pipeline/run`:
        - If `result.status === 'validation_failed'`, respond with HTTP 422 Unprocessable Entity with `result`.
  </action>
  <verify>node -e "const p = require('./src/routes/pipeline'); console.log('Pipeline route ready');"</verify>
  <done>Backend pipeline rejects scans with 422 validation_failed if roles, locations, boards, or profile baseline are missing.</done>
</task>

  <files>public/index.html, public/js/opportunities.js</files>
  <action>
    - In `public/index.html`:
      * Add modern modal `#scan-validation-modal` with clean backdrop:
        - Header: "Search Setup Incomplete" with amber caution badge.
        - Description: "To discover and accurately score jobs tailored to you, please complete the following setup requirements:"
        - Visual Checklist Container `#scan-validation-checklist`:
          * 🎯 Target Job Roles: (e.g. "Missing — Add at least 1 role")
          * 📍 Target Country & Cities: (e.g. "Missing — Select country and at least 1 city")

      * Update `triggerPipelineScan()`:
        - Calls `validateScanPreconditions()` before sending `POST /api/pipeline/run`.
        - If backend returns 422 `validation_failed`, parses `data.validationErrors` and renders the checklist modal with server-provided error messages.
  </action>
  <verify>grep -i "scan-validation-modal" public/index.html</verify>

## Success Criteria
- [ ] Scanning with zero roles, zero locations, or all boards disabled is cleanly intercepted on both client and server.
- [ ] Users are presented with a clear visual checklist indicating exactly what is missing.
- [ ] 1-tap action buttons immediately navigate the user to the correct tab and input to fix the missing criteria.
