# Plan 32.2: Replace "Pass" with Delete 🗑️ Permanent Delete (Purge from DB, Keep seen_jobs Dedup Memory)

## Objective
Replace the "Pass" button on each opportunity card with a trash-can button. Deleting a job permanently removes it
from Opportunities and from the database (`pending_jobs`, `rejected_jobs`, `tailored_resumes`, and the cached
artifacts under `data/tailored/<id>/`). Its id is **kept or added** in `seen_jobs`, so later scans never show it again
(the pipeline dedup in `src/routes/pipeline.js` L283 already filters against `seen_jobs`).

Depends on 32.1 because both plans edit the card action bar and job routes in `opportunities.js` / `jobs.js`.

## Context
- `public/js/opportunities.js` (action bar L434-458, `rejectJob()` L981, window exports L1005+)
- `src/routes/jobs.js` (`POST /reject` L117, `DELETE /:id` L171 — applied-only, must stay as is)
- `scripts/core/jobs-db.js` (`removePendingJob()` L549, `markJobSeen()` L458, `findJobRecord()` L557, module.exports)
- `scripts/engine/tailor-engine.js` (`getTailoredArtifactPaths()` — export already exists)
- `src/routes/pipeline.js` L283 (dedup against seen_jobs, pending, applied, rejected)

  <action>
    - In `jobs-db.js`, add `purgeOpportunity(jobId)` and export it. The DB is `node:sqlite` `DatabaseSync`, which has
      NO `.transaction()` helper. Wrap the steps in `db.exec('BEGIN')` … `db.exec('COMMIT')`, with `db.exec('ROLLBACK')` in `catch`:
      1. Collect ids: `jobId`, plus `id`/`job_id` from the matching `pending_jobs` row, plus the raw-id variants that `findJobRecord` matches.
      2. `INSERT OR IGNORE INTO seen_jobs` for each id, lower-cased (same convention as `markJobSeen`). This guarantees the job is never re-surfaced.
      3. `DELETE FROM pending_jobs WHERE id = ? OR job_id = ?`
      4. `DELETE FROM rejected_jobs WHERE id = ? OR job_id = ?`
      5. `DELETE FROM tailored_resumes WHERE id = ? OR job_id = ?`, but ONLY if there is no `applied_jobs` row for that id (never touch My Applications).
      6. Never delete from `seen_jobs` or `applied_jobs`.
      Return `{ removed: <pending rows deleted>, idsSeen: [...] }`.
    - In `routes/jobs.js` (add `const fs = require('fs');` and import `getTailoredArtifactPaths` from tailor-engine — neither is imported today), add `DELETE /pending/:id` (it has 2 path segments, so it can't collide with `DELETE /:id`):
      call `purgeOpportunity`, then best-effort `fs.rmSync(getTailoredArtifactPaths(safeId).folder, { recursive: true, force: true })`
      only when the job is not in `applied_jobs`. `safeId` uses the same sanitisation as tailor-engine: `/[^a-zA-Z0-9_-]/g → '_'`.
      Respond `{ success: true, id, removed }`.
    - Leave `POST /api/jobs/reject` in place for API/test compatibility; nothing in the UI calls it anymore.
