# Plan 31.3: Balanced HR-Calibrated Scoring Engine & Opportunities Filter Alignment

## Objective
Re-engineer the scoring calculations to eliminate artificial score inflation (where matching 3-4 skills out of 30 was awarding 85-92% scores). Think like an encouraging HR reviewer: evaluate how many required skills the candidate actually possesses, give a 15-20% favorable baseline on transferable qualifications, but allow partial matches to land naturally in the 55%–75% range. Calibrate unstated skills defaults to 70% (instead of 90%). Align Opportunities page filter chips and threshold badge to dynamically reflect the user's configured threshold (e.g. 65%).

## Context
- `scripts/engine/node-logic.js`
- `scripts/engine/scoring-v2.js`
- `prompts/job-scoring.txt`
- `src/routes/pipeline.js`
- `public/js/opportunities.js`
- `public/index.html`
- `tests/test-hr-calibrated-scoring-and-ingestion.test.js`

  <name>Re-Calibrate Heuristic & LLM Scoring to HR-Balanced Standards</name>
  <files>scripts/engine/node-logic.js, prompts/job-scoring.txt, src/routes/pipeline.js</files>
  <action>
    - In `scripts/engine/node-logic.js` inside `computeHeuristicScore()`:
      1. Overhaul `skillsScore` calculation:
         - Eliminate the artificial `60 + (matched / 5) * 40` floor that was awarding 84% for 3 matched skills.
         - Implement an HR-calibrated formula:
           * If 0 skills match and full description exists: score skills at 35–45% (poor fit).
           * If 1-2 skills match: score skills at 50–60% (partial/stretch fit).
           * If 3-5 core skills match: score skills at 65–75% (solid fit).
           * If 6+ core skills match or high percentage of requirements: score skills at 80–95% (exceptional fit).
           * Add an HR favorability bonus (+10-15%) for exact job title match and seniority alignment, but NEVER award 85%+ overall score if the candidate only matches a tiny minority of stated technical requirements.
      2. If skills are unstated or description is very brief (< 150 chars):
         - Set `skillsScore = 70` (neutral screening tier) instead of an inflated `90`.
    - In `prompts/job-scoring.txt`:
      - Update instruction: "If no specific technical skills are mentioned in posting, assign skills_fit_score = 70 (Neutral/Screening tier)" instead of 90.
      - Add guidance: "A candidate who only matches 3-4 skills out of 20-30 stated requirements should be scored around 50-60% on skills fit. Do not inflate skills fit above 75% unless the candidate possesses the majority of primary required tools."
    - In `src/routes/pipeline.js`:
      - Increase LLM scoring timeout from 4500ms to 7000ms and tune worker concurrency so authentic LLM evaluations run reliably without prematurely dropping to heuristic fallback.
  </action>
