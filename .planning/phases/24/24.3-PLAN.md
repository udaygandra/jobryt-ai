# Plan 24.3: Scoring v2 — Location as Gate, Re-weighted Pillars

## Objective
The user already chose where they will work and how far they will travel (Settings). Treating location as a 30% *scored* pillar double-penalises/over-rewards it: a job inside the radius is simply acceptable, and one outside it is already excluded. Make location a **hard gate + light proximity preference**, and move the freed weight to what actually differentiates candidates: skills, seniority and function match.

## Design

**Gate (not a score):** `eligible = remote-in-scope OR distance <= radius OR within user-selected city/region`. Fail → `should_apply=false`, overall capped at 45, reason recorded. Computed 100% in code (Haversine, Phase 23) — never by the LLM.

**Weights (v2):**

| Pillar | v1 | v2 | Who computes | Notes |
|--------|----|----|--------------|-------|
| Skills | 40 | **45** | LLM evidence + code ratio | required skills weigh 2x nice-to-have; unstated skills → 90 baseline (kept) |
| Seniority | 30 | **30** | code rules + LLM years | exec/manager/lead mismatch gates unchanged |
| Function/Title | 0 (deprecated, fixed 90) | **10** | LLM | duties-based, so title wording quirks don't kill matches |
| Location | 30 | **15** | code | remote = 100; in radius = 100 → 85 linear with distance/radius; hybrid ≥ remote-tier penalty-free if inside radius |

`overall = round(0.45*S + 0.30*Sen + 0.10*F + 0.15*L)`; any gate/disqualification → min(overall, 45).

**Why this is fairer across personas:** remote-only dev no longer gets an automatic +30 from location (score reflects skills); nurse/trades onsite roles at 3km vs 20km differ by ≤ 2.3 points (they both passed the user's own radius); a senior candidate is no longer dragged down by a fixed 30% they cannot influence; extra `F` weight rescues strong-function/odd-title matches.

**Threshold guidance:** default `score_threshold` 65 (was 70 in this install); show a "near-miss (60-64)" bucket in Opportunities rather than hiding them, since location is no longer inflating scores.
