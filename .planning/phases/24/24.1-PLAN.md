# Plan 24.1: Per-Task Search Context & Bounded-Concurrency Fetch Pool

## Objective
`fetchAllJobs` sweeps role × location pairs **sequentially** (with an 800ms sleep) because every fetcher reads module-global `currentRole` / `currentLoc`. Boards inside a pair already run in parallel, but pairs, Adzuna pages, and LinkedIn detail pages do not. Replace the globals with an immutable per-task `ctx` and run all (board × role × location × page) tasks through a bounded, per-host rate-limited pool so a scan finishes in a fraction of the time with no 429 storms.

## Context
- scripts/engine/fetch-all-boards.js (`fetchAllJobs` ~L1531, `fetchAdzuna`, `fetchLinkedIn`, `fetchCanadaJobBank`)
- src/routes/pipeline.js (scan trigger, passes options)
- Node `worker_threads` / child processes are NOT needed: work is I/O-bound, so async concurrency is faster and simpler (no serialization cost, shared dedupe set).
